# Wave 51 BV-10: authenticated recovery context

Date: 2026-09-18. Starting point: `2abb416`. Scope: additive vault-library
recovery metadata, tests and ledger wording. No funded output, key derivation,
HKDF bytes, service, deployment or activation was changed.

## Local hardening

Wave 50 introduced `RecoveryContextV1`, but its public backup bytes were not
self-authenticating. An attacker able to replace a backup could change the
derivation selector or vault ID. The independent funded `H(r)` comparison made
that substitution fail during restoration, but there was no way to distinguish
corruption from metadata signed by the vault owner before attempting restore.

`SignedRecoveryContextV1` is an opt-in envelope around those unchanged canonical
bytes. It provides:

- a distinct signature domain plus an explicit context-length prefix;
- the existing hybrid PQ signature generated by the vault owner's PQ secret;
- verification only against a PQ public key supplied independently of the
  backup, never a self-declared key inside it;
- a fail-closed `verify_and_restore` path that authenticates metadata before
  applying its derivation selector, then retains the funded hash/network checks;
- strict magic/version/reserved fields, exact lengths, no trailing bytes and an
  8 KiB defensive signature limit; and
- producer-side refusal if a present or future signer emits an empty or
  over-limit signature, avoiding a truncating length cast.

The original unsigned context codec and all V1/V2/V3 derivations remain
byte-compatible. Existing recovery workflows are not silently reinterpreted.

## Tests

The vault suite covers signed encode/decode, independent trusted-key
verification, checked restoration, wrong-key refusal, signature tampering,
metadata substitution, every truncated prefix, trailing data, unknown version,
nonzero reserved byte, empty signature and over-limit declared signature.

Validation:

- `cargo test --locked -p bloch-pq-vault --offline`: 42 passed;
- `git diff --check`: run at integration after the parallel Wave 51 changes.

## Honest residual boundary

BV-10 remains `PARTIAL`. A signature authenticates the context only when the
restoring party already has the correct owner public key. The library does not
distribute or register that trust anchor, allocate globally unique vault IDs,
detect the same ID across independent backups, observe preimage publication,
enforce single use, authenticate an entire backup container, or prove PQ-key
possession to Bitcoin. Product adoption and lifecycle state remain required.

Ledger aggregate counts are unchanged: this narrows one existing partial
finding and does not claim production deployment or external audit evidence.
