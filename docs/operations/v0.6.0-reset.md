# GroundState v0.6.0 Reset Procedure

The v0.6.0 release is a **consensus-breaking hard fork**: new genesis
block, new difficulty bits, Bitcoin-format wire serialization (Sprint 1),
and a live stratum V1 server (Sprint 2). The pre-v0.6.0 chain at
block 2675 cannot be migrated — it must be wiped and relaunched from
genesis.

This document walks an operator through the full procedure: calibrate
`GENESIS_BITS`, patch source, build Docker image, wipe the seed,
restart, redeploy workers, announce.

Total wall-clock: ~4–6 hours for a careful first-time execution.
Most of that is Docker image build on an ARM Mac (amd64 emulation)
and waiting for replicas to restart.

---

## Phase 1 — Calibrate GENESIS_BITS (30–60 min)

### 1.1 Measure seed hashrate

On the seed machine (`ssh grnd`):

```bash
# Build the calibration tool
cd ~/groundstate  # or wherever the source lives on the seed
cargo build --release --bin grnd-calibrate

# Measure for 2 minutes on all CPUs
./target/release/grnd-calibrate --duration 120
```

Record the final `Raw hashrate` number. Expect ~1 Mhash/s on a 1-vCPU
Njalla VPS.

### 1.2 Measure worker hashrate

For each Akash worker (or any other machine that will mine at launch),
SSH in or use the Akash shell and run the same command:

```bash
./target/release/grnd-calibrate --duration 120
```

On typical 8-vCPU Akash containers expect ~20–30 Mhash/s depending on
CPU generation.

### 1.3 Sum measured hashrates

```
seed:       1 000 000  H/s
worker-1:  22 000 000  H/s
-------------------------
total:     23 000 000  H/s
```

### 1.4 Compute GENESIS_BITS for this total

From any machine with the source tree:

```bash
./target/release/grnd-calibrate \
    --hashrate 23000000 \
    --target-time 10 \
    --margin-pct 15
```

Output ends with something like:

```
Recommended GENESIS_BITS
  bits:              0x1d013a92  (486772882)

Next steps
  1. Edit src/core/mod.rs:
     pub const GENESIS_BITS: u32 = 0x1d013a92;
```

**Copy that hex value.** It's the one compile-time constant you need
to patch before building the release image.

### 1.5 Safety-margin sanity check

The tool applies `--margin-pct 15` by default, meaning the computed
bits targets blocks at 10s assuming the network runs at 85% of the
measured raw hashrate. This absorbs:

- Thermal throttling under sustained load
- Akash co-tenancy noise
- One worker being temporarily offline

If you expect to add more workers quickly, use a larger margin
(20–25%) — the chain will just run blocks slightly faster than 10s,
which is fine. Under-estimating is much worse: if the network runs
slower than calibrated, blocks take 20s+ and the chain appears
stalled to observers.

## Phase 2 — Patch source + rebuild Docker image (60–90 min)

### 2.1 Update the constant

```bash
cd ~/groundstate

# Edit src/core/mod.rs and change
#   pub const GENESIS_BITS: u32 = 0x1d00ffff;
# to whatever grnd-calibrate recommended, e.g.:
#   pub const GENESIS_BITS: u32 = 0x1d013a92;

# Verify compile
cargo check --lib

# Run the full test suite to catch any assumption about the old bits
cargo test --lib 2>&1 | tail -5
cargo test --test sprint1_bitcoin_format 2>&1 | tail -3
cargo test --test sprint_aa0_mining_header 2>&1 | tail -3
cargo test --test sprint_u3_reorg 2>&1 | tail -3
```

Commit:

```bash
git add src/core/mod.rs
git commit -m "v0.6.0 release — GENESIS_BITS calibrated for ~23 Mhash/s @ 10s block time

Calibrated via grnd-calibrate --hashrate 23000000 --target-time 10
--margin-pct 15. Tool output produces the recommended bits value
based on: seed (1 Mhash) + akash-worker-1 (22 Mhash) measured
2026-MM-DD.

The 15% margin absorbs thermal throttling + Akash co-tenancy noise.
Expected initial block time: ~8.5s under ideal conditions.
Retarget will adjust within the first 2016 blocks."

git tag -a v0.6.0 -m "GroundState v0.6.0 — Stratum V1 + Bitcoin-format consensus fork"

git push origin main
git push origin v0.6.0
```

### 2.2 Build Docker image

```bash
# Mac arm64 → linux amd64 cross-build via emulation.
# First time this takes ~40-60 min. Subsequent builds are incremental.

docker buildx build \
    --platform linux/amd64 \
    --tag groundstate100/groundstate:v0.6.0 \
    --tag groundstate100/groundstate:latest \
    --push \
    .
```

Verify the manifest:

```bash
docker buildx imagetools inspect groundstate100/groundstate:v0.6.0
```

Should show `os: linux, arch: amd64, os.version:` etc. Record the
digest (`sha256:...`) — you'll pin that in the Akash SDL.

## Phase 3 — Seed wipe + restart (15–30 min)

**WARNING:** This step destroys the pre-v0.6.0 chain irreversibly.
Ensure Phases 1 and 2 are verified before proceeding. There is no
rollback path.

### 3.1 Stop the seed

```bash
ssh grnd
docker ps     # confirm container id/name
docker stop grnd-seed   # or whatever the container name is
```

### 3.2 Snapshot the old data-dir (paranoia)

```bash
# Create a one-time safety copy in case you want to forensically
# examine the pre-reset chain later. Delete after launch is stable.
sudo mv /opt/grnd-data /opt/grnd-data-v0.5.13-snapshot-$(date +%Y%m%d)
sudo mkdir -p /opt/grnd-data
sudo chown 1000:1000 /opt/grnd-data   # match uid/gid inside container
```

### 3.3 Pull the new image

```bash
docker pull groundstate100/groundstate:v0.6.0
```

### 3.4 Start v0.6.0

The seed's systemd unit or docker-compose should already reference
`groundstate100/groundstate:v0.6.0` (or be updated now). Then:

```bash
docker run -d \
    --name grnd-seed \
    --restart unless-stopped \
    -p 16110:16110 -p 16210:16210 -p 3333:3333 \
    -v /opt/grnd-data:/data \
    groundstate100/groundstate:v0.6.0 \
    --data-dir /data \
    --listen /ip4/0.0.0.0/tcp/16110 \
    --rpc-bind 0.0.0.0 --rpc-public \
    --stratum --stratum-addr 0.0.0.0:3333 \
    --mine \
    --miner-address grnd1q4fbcd3b3fae5de3e2b4015ca132c8744b8af170a79e4eb45
```

Watch the logs for the first 30 seconds:

```bash
docker logs -f grnd-seed
```

You should see:

```
⛏  Miner started → grnd1q4fbc...
stratum: binding 0.0.0.0:3333 mode=solo
stratum: listening on 0.0.0.0:3333
⛏  Block found! h=1 ...
```

If block 1 takes more than 60 seconds to appear, difficulty is too
hard — `GENESIS_BITS` was miscalibrated. Stop, roll back to old
image, re-measure, try again.

### 3.5 Verify via RPC

From any machine:

```bash
curl -s http://SEED_IP:16210/ \
    -d '{"jsonrpc":"2.0","method":"getinfo","id":1}' | jq .

# Should return version: "0.6.0", block_count > 0 within 30s
```

## Phase 4 — Redeploy Akash workers (30–60 min)

For each worker deployment:

### 4.1 Close the old lease

```bash
akash tx deployment close \
    --dseq <old_deployment_sequence> \
    --from wallet --fees 5000uakt
```

### 4.2 Update the SDL

The worker SDL (typically `deploy/akash/worker-stratum.yml`) must:

1. Point to `groundstate100/groundstate:v0.6.0` (or pin the digest)
2. Remove `--mine` (workers mine via stratum now, not built-in)
3. Add stratum client config pointing to the seed:
   `--stratum-upstream stratum+tcp://SEED_IP:3333`

Actually: the worker runs cpuminer (or similar) pointed at the seed's
stratum, NOT the full node binary. So the SDL changes shape:

```yaml
services:
  cpuminer:
    image: groundstate100/cpuminer-groundstate:latest
    command:
      - "-o"
      - "stratum+tcp://SEED_IP:3333"
      - "-u"
      - "grnd1q4fbc..."  # worker's own payout address
      - "-p"
      - "x"
      - "-t"
      - "8"
```

(Alternately, keep the worker as a full node but configured to mine
via stratum — same effect, more bandwidth. For launch, cpuminer is
simpler.)

### 4.3 Deploy

```bash
cd deploy/akash
akash tx deployment create worker-stratum.yml --from wallet --fees 5000uakt
# ... accept a bid, create lease
akash provider send-manifest worker-stratum.yml --provider <addr> --dseq <new_dseq>
```

### 4.4 Verify from the seed

```bash
docker logs grnd-seed | grep stratum | tail -20
# Expect: "stratum: session N accepted from AKASH_PROVIDER_IP"
# Then:   "stratum: session N authorized grnd1q..."
# Then:   "stratum: session N notified h=M bits=..."
```

After a few minutes:

```bash
docker logs grnd-seed | grep "Block found" | tail -5
# Blocks should appear with the worker address in coinbase
```

## Rollback path (emergency only)

If within the first 24 hours the chain demonstrates a critical issue
(stuck tip, undetected fork, consensus disagreement between seed and
workers):

```bash
ssh grnd
docker stop grnd-seed
docker run -d \
    --name grnd-seed \
    --restart unless-stopped \
    # ... original flags ...
    groundstate100/groundstate:v0.5.13
```

And restore the snapshot:

```bash
sudo rm -rf /opt/grnd-data
sudo mv /opt/grnd-data-v0.5.13-snapshot-YYYYMMDD /opt/grnd-data
```

v0.5.13 image is pinned at digest
`sha256:8bd47bca9e857629262026e9cea8442db158ee8449937f019ca5b0c8eb7c434d`.

If rolling back, post an immediate status update: operators who
already upgraded to v0.6.0 will have their nodes rejected by peers
still on v0.5.13 (and vice versa). Communication is critical.

## Post-launch checklist (first 48 hours)

- [ ] Block time holding near 10s target (±30% is fine)
- [ ] Retarget at block 2016 produces sensible new bits
- [ ] Stratum server shows steady session count (no churn)
- [ ] No "block rejected" logs on seed
- [ ] At least one mined block per worker in the first hour
- [ ] Explorer indexing from block 1
- [ ] RPC `getinfo` returns consistent state from seed + workers

If all green for 48 hours, v0.6.0 is stable. Schedule Sprint 2.e
(integration test) + Sprint 3 (Stratum V2) + Sprint 7 (shared template
optimization) for subsequent iteration.
