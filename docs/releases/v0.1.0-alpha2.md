## Consensus — difficulty-driven progressive k-ramp (retires the k=8 jump)

The residual-gate width `k` no longer jumps to 8 at a fixed height. The old
`CANONICAL_K_ACTIVATION_HEIGHT = 40_320` had been misapplied onto a chain
already at ~394k, firing k=8 and **choking block production at low hashrate for
no security gain** — the source flags *both* k=4 and k=8 as the **trivial q-ary
regime** at `β = q/16`, so raising `k` buys **no cryptographic hardness**. Real
security is, and stays, **cumulative SHAKE-256 hashcash work**.

The replacement is a **Bitcoin-model ramp**: `k` rides the block's own **ASERT
difficulty** (`bits_to_work`) — the on-chain hashrate proxy.

- **k = 4** below `K_RULE_ACTIVATION_HEIGHT` (a **future** height so every node
  upgrades first → **no fork**), then **k rises 5 → 6 → 7 → 8** as sustained
  difficulty crosses ~8×-spaced work thresholds (`K_WORK_5..8`), and **eases
  back if hashrate falls** (self-healing — a capacity crash can't re-choke).
- **Deterministic**: `bits` is consensus-validated (ASERT-retargeted, not
  miner-chosen), so every node computes the same `k`.
- **Backward-safe**: existing k=8 blocks stay valid (`k=8 ⊃ k=4`).
- `canonical_residual_coeffs(height, bits)`; the `K_WORK_*` thresholds are a
  calibration knob. `k` is a **structural/throughput filter, not a hardness
  claim.** New ramp tests green; node compiles.

## Peering / networking — non-consensus operator knobs

- `--max-peers <N>` (the ~50-peer wall is now an operator setting; public
  bootstrap runs 500).
- `--dns-seed <host>` opt-in cold-start (`DEFAULT_SEEDS` stays empty).
- `--behind-proxy` disables the gossipsub IP-colocation penalty behind a cloud
  proxy (same-source peers were being graylisted).
- IBD-latch release so a joined node actually mines; fresh-miner fork guard;
  the on-connect subscribe/tip race fixed.

## Consensus fixes

- **DAG-ordering consensus-halt** (reorg over an over-deep fork) fixed.
- Security-audit fixes: C1/C2 criticals, H2/H3/H4, and wallet/PoW lows.

## Rollout

Coordinated upgrade: every operating node should run this build **before**
`K_RULE_ACTIVATION_HEIGHT`, so no node validates differently mid-flight. Re-pin
`K_RULE_ACTIVATION_HEIGHT` against the real tip at rollout.
