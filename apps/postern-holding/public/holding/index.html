05 / Software + network updates

A stronger node.
The next chapter.

The signed Genesis-4 node release improves validator safety, network reliability and finality verification. Released node features and future network upgrades are shown separately below.

Released 21 October 2026 / Linux x86-64 / 1708953d

Validator hardening, now released.

Durable signing history, host-level signer locking and a strict signer anchor protect validator operation across restarts and restored data. Duplicate-validator detection checks for unexpected signatures from the same identity.

Safer signing

Signing records are saved before signatures are released. A host-level lock prevents a second local signer from using the same identity.

More reliable participation

Improved attestation retries and stricter node-local ML-DSA relay verification strengthen day-to-day node operation.

Verifiable finality

The finality-certificate RPC exposes proof data for independent verification against a trusted earlier checkpoint.

All 61 managed fleet validators were upgraded and verified on 22 October 2026. This release schedules no new hard fork; new consensus activation gates remain disabled.

For existing Genesis-4 nodes. Verify the signed checksum before installation and preserve validator identity, signing history and signer anchor.

Coming next.

These consensus changes remain disabled in the released binary. Activation requires a separately qualified and announced network upgrade.

Post-quantum signatures / not active

An optional hash-based suite.

  • The hybrid ML-DSA-65 + Falcon-1024 construction stays the default.
  • An optional SLH-DSA + Falcon-1024 suite for cold storage, treasury and long-term holdings.
  • A hash-based floor if lattice cryptography is weakened.
Consensus / not active

Finality under network partitions.

  • Finality counted over a frozen validator set.
  • Votes counted only for the voter’s own chain.
  • Activation remains subject to further qualification.
Validators / not active

Key-evolving signatures.

  • KES for validators.
  • Forward-secure validator keys.
