Participate

What running a node will take.

Genesis-4 validators stake a bond, run duties on a 30-second clock, and share slashing risk with anyone who delegates to them. The parameters below are in the code today; the network is not. Both facts belong on the same page.

Validating

The bond, the queue, the exit.

Planned

25,000 BLCH bond

Roughly the fraction of supply Ethereum asks for with 32 ETH. It lowers who may validate; it does nothing about who does — a large holder can fund many validators, and the 1% cap binds per validator, not per owner.

Planned

A visible queue

Deposits activate through a public queue — 4 validators per epoch, after an ~2.1-hour delay; exits take ~8.5 hours. Taking over the set requires weeks of traffic everyone can watch.

Planned

Delegation

Stake behind an operator without running hardware — and share their slashing risk, pro-rata. That exposure is the point: a delegator who cannot lose anything has no reason to choose operators carefully.

What exists today

A devnet node and a chain about to halt.

Not ready

The PoS node is devnet

It produces, attests and finalises across real processes — a running devnet, not a diagram. It has no persistent store, no gossip network, no transactions, no slashing pipeline and no RPC yet. There is no Genesis-4 launch date, and anyone quoting one is guessing.

Ending by design

Genesis-3 mining stops at 50,000

The proof-of-work chain halts at height 50,000, so standing up new mining now buys days, not months. New nodes bootstrap from a datadir snapshot — from-scratch sync is no longer supported on the live network.

Hardware

What it actually takes to run one.

The Genesis-3 column is measured on the live fleet, not estimated — three boxes running the archival node today. The Genesis-4 column is a projection from the same measurements plus the signature and bandwidth arithmetic, and it is labelled as a projection because the proof-of-stake node has never run outside a devnet.

Why so small

The chain is young

452 MB is not an achievement of engineering — it is what 37,960 blocks weigh. A chain with years of history behind it would ask for far more, and Genesis-4 will grow into that over time.

The expensive part

Signatures, not computation

A hybrid ML-DSA-65 ‖ Falcon-1024 signature is ~4.6 KB and one verification costs about 7.3 million instructions. Bandwidth and verification scale with the validator count, not with transaction volume — the opposite of most chains.

Not a recommendation

These are floors

Nothing here has been through a load test at a realistic validator count. The proof-of-stake node has run four processes on one machine, which tells you it works and tells you nothing about a thousand of them across the internet.

Copyleft, on purpose.

The protocol implementation is licensed AGPL-3.0-or-later: anyone may run it, study it, fork it — and anyone who operates a modified version for others must publish their changes. For consensus software that is not idealism, it is how everyone verifies they are running the same rules.

What is not there yet

Read before you judge the tree

The proof-of-stake node runs on a devnet: no transactions, no peer-to-peer stack, no public RPC. 30% of code files still carry no SPDX header. Neither is hidden, and both are in the audit notes in docs/.
