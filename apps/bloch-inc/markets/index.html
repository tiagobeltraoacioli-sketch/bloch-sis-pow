Market infrastructure

Bloch Markets is a proposed software platform for builders and operators of eligible digital assets. It brings the Ustav programmable token into a coherent path for creation, policy, data and, once qualified, liquidity integration.

Product thesis

Software infrastructure

Give digital assets
usable rails.

Offer reusable software components rather than operating a marketplace: programmable tokens, lifecycle APIs, event records and reconciliation tools. Teams remain responsible for their own assets, policies and operations.

Product + service modules

One foundation.
Four service layers.

Each layer can be evaluated independently. Production availability depends on its own engineering and security gate.

01 / token engine

Ustav programmable token

Define an eligible native asset and apply programmable controls for registration, supply, transfers, burns and policy changes. The current implementation is a local reference kernel.

Existing: locally executable code / future: live node integration
02 / developer platform

Lifecycle APIs + sandbox

Proposed APIs, SDK examples and a repeatable sandbox for asset configuration, policy tests and application integration.

Proposed service / requires stable API and node activation
03 / operations

Events, data + reconciliation

Proposed event streams, indexed asset histories, operator views and exportable records that help teams reconcile their own workflows.

Proposed service / requires complete indexing and observability
04 / liquidity interface

Bloch DEX adapter

A future native path from eligible Ustav assets to Bloch DEX AMM pools, subject to live native execution, audited pool logic, asset eligibility and operational controls.

Research and local prototype / no live native AMM

Current status / September 2026

The evidence
behind the proposal.

Local prototypes demonstrate technical directions. A hosted service needs live network integration and independent qualification.

Available locally

Ustav token lifecycle

Registration, minting, transfers, burns and policy updates run in the repository's local reference kernel.

Available locally

Native pair + pool prototypes

Atomic native pairs and supply-only token pool custody run in separate local implementations. The pool rejects base BLCH.

Not activated

Genesis-4 integration

Ustav is not a dependency of the live Genesis-4 node. Production signing, execution, indexing and service operations need integration.

Not activated

Native Bloch DEX AMM

No live native pool or Bloch Markets trading path is offered. Qualification requires security review, asset rules and operational readiness.

Service scope: software infrastructure for eligible digital assets. Bloch Markets does not offer securities issuance, brokerage, custody, fiat payment rails or operation of a regulated exchange.

Delivery sequence

Qualify each step
before the next.

The sequence is directional. It does not promise launch dates or production access.

  1. 01

    Ustav sandbox

    Package local token and policy examples with repeatable tests and documented asset eligibility.

  2. 02

    Live token infrastructure

    Integrate native execution into the node, prove authorization and finality, then expose versioned lifecycle APIs and index data.

  3. 03

    Operator services

    Qualify event delivery, reconciliation, monitoring, recovery and support procedures for a limited service pilot.

  4. 04

    DEX liquidity adapter

    Only after native pool audit and live network qualification, connect eligible assets to Bloch DEX liquidity interfaces.
