Architectural principle

Interoperability is a boundary,
not a security shortcut.

Distinct authorization domains require distinct trust assumptions. A cross-chain path must be assessed end to end.

Bloch L1 / native domain

Post-quantum authorization

Native L1 fund movement retains the ML-DSA-65 + Falcon-1024 authorization boundary. ECDSA does not apply here.

PQ
Verification
boundary
Bloch L2 / EVM domain

ECDSA applies to L2 only

Bloch L2 accounts and contracts use ECDSA and retain separate security assumptions. Settlement on Bloch L1 remains in development.

EVM

ECDSA is confined to Bloch L2/EVM. A bridge, L2 account or wrapped asset does not automatically inherit Bloch L1's native post-quantum guarantees.

Evidence-led roadmap

Four delivery gates.
One accountable sequence.

Each gate requires a documented network result before the next product claim. These are priorities, not fixed launch dates.

G0 / reliable base

Prove the foundation

Regular checkpoints, fresh independent node sync, reproducible releases and compared finality evidence.

Unlocks: production qualification for Verify.
G1 / data + integration

Make data usable

Complete index, versioned API, webhooks, SDK examples, monitoring and support procedures.

Unlocks: Data + Dev Cloud pilots.
G2 / value workflows

Control real flows

Treasury policies, reconciliation, documented credit rules and a controlled partner pilot.

Unlocks: Treasury + Pay evaluation.
G3 / markets + networks

Qualify expansion

Bridge, L2, eligible digital-asset infrastructure and LatAm pilots with verified finality, audit and recovery.

Unlocks: limited service decisions after each boundary is verified.
GLOBAL PATH

Ustav sandbox → token lifecycle APIs → qualified Bloch DEX liquidity adapters for eligible assets.

LATAM PATH

Read-only rail observation → partner reconciliation → controlled regional corridors.

Progress is measured by verified capability, not by a fixed launch-date promise. The network remains open; company services are optional.
