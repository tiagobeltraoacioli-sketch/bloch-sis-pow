# Bloch Ops

Static operations portal for `ops-blochinc.xyz`. It distinguishes published Genesis-4 network entry points and operator guides from planned managed APIs and unactivated delegation.

The portal has dedicated `/monitor/`, `/rpc/`, `/validators/`, `/wallets/` and `/pq-shield/` pages. The wallet page distributes Genesis-4 SDK 0.1.13, including local wallet creation and recovery, a one-call included deposit query by txid, address and amount, signed transfer construction with byte-correlation checks at broadcast, read-only tracking of a stored signed transfer after an ambiguous timeout, structurally validated included receipt lookup, comparison of successive transaction observations, and exact output matching for deposit reconciliation. It includes an explicit source-only UTXO cursor mode, disabled by default until a supporting node release is deployed. Its read-only browser inspector rejects incomplete or contradictory receipts, compares repeated lookups within the current tab, and locally matches public script hashes and integer satoshi totals for deposit review. The page does not accept a mnemonic or sign in the browser. The validator page uses the live `getvalidatoradmission` response to describe funded admission and publishes a versioned operator onboarding worksheet; the full mainnet exit and withdrawal cycle still requires qualification. Delegation remains inactive.

The wallet page also publishes [`wallets/transaction-query.openapi.json`](wallets/transaction-query.openapi.json), a versioned OpenAPI 3.1 contract for the public archival `GET /api/v1/transactions/{txid}` route. It records the included receipt fields required by the SDK, decimal-string satoshi amounts, and the observed 404 response. The contract was checked against a live included receipt and a missing txid on 2026-09-23. A 404 means only that no canonical archival receipt was available at lookup time; it is not a failed-transaction verdict.

After a valid included lookup, the wallet inspector can download a `bloch.genesis4.reconciliation-evidence.v2` JSON record. It contains a selected public receipt, the browser's UTC observation time, the previous public observation from that tab, its comparison, and an optional exact script-hash/amount output match. Unknown API properties are omitted. A portable Node.js verifier bundle recalculates the local claims from saved data and rejects inconsistent files; v1 files lack the prior observation and are not supported by this verifier. The file is a local observation for exchange recordkeeping, not a signed indexer attestation or a credit decision; consumers must re-query the source and apply their own ownership, confirmation and finality policy.

The browser inspector accepts a checksummed Genesis-4 mainnet deposit address or an explicit 64-character public script hash for output matching. It derives the script hash locally using a pinned copy of the SDK's `g4.cjs` address checker; a test ensures the copy remains byte-identical. Testnet and bad-checksum addresses are rejected. The evidence export records the derived script hash, while only the txid is sent to the public lookup API.

The PQ Shield section describes the repository's non-custodial Bitcoin reference API. Its local runner starts and stops the Rust service and uses disposable public test seeds to verify commitment bytes, signature acceptance, tamper and wrong-key rejection, serialized-anchor acceptance, malformed or secret-shaped HTTP request rejections, and the local service's 64 KiB JSON body limit. The loopback client handles plain-text 413 and other malformed HTTP errors without echoing server bodies. It does not claim a deployed customer service, chain-native PQ authorization on Bitcoin, or production security review.

The RPC page refreshes gateway chain and build observations and labels reported corroboration separately from independent verification. It keeps up to 120 browser-tab observations, flags reported chain regressions, exports JSON or CSV with sample limitations, and publishes a versioned source-derived read-only method catalog and compatibility probe. The probe can compare an independently supplied network domain and a second RPC's finalized checkpoint; an offline comparator checks two saved reports for domain changes and finality regressions. A separate explicit, bounded probe compares a self-reported build marker with actual source-only UTXO cursor responses without claiming mainnet availability. Failed or invalid chain refreshes clear the current figures while preserving earlier observations in history. The validator page refreshes funded admission with unavailable and stale states. It distributes a read-only Node.js preflight tool, a local checkpoint verifier, and an offline evidence assessment that checks integrity, report freshness, internal consistency and cross-report consistency while preserving manual gates; optional authenticated source, binary and signer-set digests can be pinned. The PQ Shield page provides a loopback-only Node.js client and regtest workflow, local contract and route checks using public fixtures, offline response tests, and a machine-readable OpenAPI contract; it never asks the browser for keys or sends a request to a hosted PQ Shield service.

Deploy from this directory with `wrangler pages deploy . --project-name bloch-ops --branch main` so that `functions/api/indexer-health.js` is compiled. The Cloudflare Pages project is `bloch-ops`. The custom domain `ops-blochinc.xyz` is active. The root `_headers` file permits read-only browser calls to the published Postern Labs RPC gateway and Bloch Explorer transaction API.

## Operations monitor

`/monitor/` samples six public read sources: chain state, validators, admission, mempool and build metadata through `https://posternlabs.com/g4rpc`, plus `https://blochl1.com/indexer/health` through `/api/indexer-health`. The fixed relay is needed because the upstream does not allow browser CORS reads. It accepts only GET with no query parameters, forwards no caller headers or credentials, rejects redirects, validates a bounded 1 MiB response, times out after 12 seconds, and never caches or returns upstream error bodies. Only this route invokes a Pages Function. It makes bounded requests in batches of three, validates selected fields, records separate observation times, and retains at most 180 rounds in tab memory. Decimal stake values remain exact strings.

Nine charts cover head/finality, synchronization, indexing, queue size, validator counts, transport connections, latency and head/indexer difference. The dependency graph is navigable by mouse or keyboard. Independent snapshots are not an atomic view or consensus attestation; connections are not network-wide unique peer counts.

Local thresholds flag availability, latency, finality distance, synchronization, indexer lag, queue occupancy, reported corroboration, admission, regressions and sustained lack of progress. Optional network-domain and source-digest pins compare reported values. Missing or stale observations clear current headline values and leave unresolved conditions awaiting evidence; local acknowledgement does not resolve a condition. Polling can be paused, and hidden tabs do not start scheduled reads.

JSON and CSV exports are explicit. A validated JSON import enters clearly marked unverified local replay with a round slider and no live requests until a new live session is started. Imported data is not authenticated. Files are bounded to 8 MiB and 180 rounds, observations to the six source contracts, and no private keys or credentials are requested. No automatic persistence is used.
